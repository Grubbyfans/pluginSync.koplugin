# PluginSync / 插件同步

个人局域网使用的 KOReader 插件下载与覆盖工具。版本号仅用于比较，是否下载安装由你决定。

流程：获取列表 → 下载到临时目录 → 确认安装 → 递归覆盖文件 → 清理临时文件 → 询问重启。

## PC 服务端

需要 Node.js 20 或更新版本，无第三方运行依赖。

```powershell
cd server
Copy-Item config.example.json config.json
```

编辑 `config.json`，将 `pluginRoot` 改成插件根目录，例如 `D:/KOReader/plugins`，里面直接存放 `demo.koplugin/` 等目录，每个插件包含 `main.lua` 和 `_meta.lua`。然后启动：

```powershell
npm start
```

macOS / Linux 使用 `cp config.example.json config.json`。相对的 `pluginRoot` 以配置文件所在目录为基准。也可以执行 `node src/server.js /path/to/config.json`。

设备填写 PC 实际局域网地址，例如 `http://192.168.1.100:3000`，不能填写 `0.0.0.0` 或 PC 的 `localhost`。设备与 PC 必须互通，必要时允许防火墙访问 TCP 3000。可用浏览器访问 `/api/health` 检查服务。

`token` 默认留空；如启用，客户端填入相同值。`exclude` 按文件或目录名称匹配，默认跳过 `.git`、`node_modules` 和系统垃圾文件。服务端跳过符号链接。每个插件最多 5000 文件、50 MiB 内容，可以调低限制。

## 安装客户端

在仓库根目录生成安装包：

```powershell
node tools/package.mjs
```

将 `dist/pluginsync.koplugin.zip` 解压到 KOReader 的 `plugins/`，得到 `plugins/pluginsync.koplugin/main.lua`，然后重启 KOReader。不要再套一层同名目录。

也可以手动创建 `plugins/pluginsync.koplugin/`，复制仓库根目录的全部 `.lua` 文件及 `pluginsync.json`。设备不需要 `server/`、`tests/` 或 Node.js。

## 使用

插件同步菜单首行显示「当前版本：0.2.4」。版本在启动时读取，自更新完成后重启才显示新版本。后续每次发布同步更新 `_meta.lua` 与 `pluginsync.json` 的版本号；打包时会检查两者一致。

### 0.2.4 HTTP 备用发现

部分网络中手动 HTTP 可连接，UDP 广播没有回复。现在 UDP 搜索无结果或不可用时，自动增加一次 HTTP 备用发现。**需要同时更新 PC 服务端代码并重启 `npm start`，客户端更新后也需重启 KOReader。**

备用发现只检查设备当前 IPv4 网段的默认 TCP 3000 及已保存地址中的端口。最多检查本机附近 /24 范围（大网段不全量扫描），排除本机、网络地址和广播地址，最多 24 个非阻塞连接并发、8 个 HTTP 候选，连接检查约最多 4 秒、备用阶段目标约 7 秒。UDP 加备用搜索一般需要约 4～11 秒，此外首次可能测试上次地址。

只有 `/api/discovery` 返回固定服务标识、API 版本与发现协议版本的地址才进入结果列表。此接口公开电脑名称与是否需要 Token，不公开插件列表、源路径或凭据；识别请求不携带 Token，不跟随重定向，响应限制为 4 KiB。选中已识别服务器后才使用 Token 测试连接。`discovery:false` 同时关闭 UDP 和 HTTP 发现接口，原有健康检查和插件 API 仍受 Token 保护。

没有配置过地址时，仅检查默认 3000 端口；非默认端口仍优先依赖 UDP，或手动设置一次。无法读取设备网段时会明确提示，保留手动连接。网络策略仍可能阻止 TCP，备用机制不保证所有网络都能发现。

### 0.2.3 搜索兼容性

搜索同时尝试已保存 IPv4 地址的 UDP 定向请求、当前 Wi-Fi 网卡的网段广播和通用广播。网段广播由真实 IP/掩码计算，不假定所有网络都是 /24；优先使用 KOReader 当前网络接口，获取失败则退回已知地址和通用广播。某一目标不可达不会中断其余目标。

未找到时显示发送次数、收到/无效响应数量、目标地址和网络错误，便于区分广播不通与协议响应不匹配。HTTP 可以连接仅说明 TCP 服务可达，UDP 3001 和广播仍可能被网络策略过滤。保留原来的手动连接、上次地址快速验证和 4 秒搜索窗口。

### 0.2.2 优化

- **本机版本**：每次刷新或重建列表优先读取本机 `pluginsync.json`，其次受限文本读取 `_meta.lua`；缺少有效版本才使用安装记录，并标注「安装记录」。手动更新实际版本文件后，刷新即可识别，不会继续使用旧记录。空白版本不算有效版本，不执行插件 Lua。
- **列表位置**：列表内刷新、普通插件安装后保留当前页，尽可能保留本页所选插件的焦点，不会因排序变化追踪到其他页；条目减少时自动回到最后有效页。标题左上角增加操作按钮，在任意页可刷新/筛选/排序，无需先翻回第一页。主动切换筛选/排序或从主页重新获取时回到第一页。
- **安装空间**：确认页展示预计需要/可用 MiB，点击安装后再次检查。按完整新文件内容保守预留空间，每文件至少按 64 KiB 对齐、目录额外预留，并加 1 MiB 余量；不依赖覆盖旧文件释放空间，也不会把已下载临时文件重复计入需求。此值是保守估计，可能高于实际增量占用。
- 通过 KOReader `ffi/util.df` 查询目标所在文件系统；优先使用可用容量，兼容旧版接口返回的空闲容量。空间不足或无法查询时，在覆盖前停止、保留临时文件供重试。检查不能保证其他进程不会随后消耗空间，仍需处理写入失败。

### 搜索局域网服务器（0.2.1）

1. **PC 端必须运行本次更新后的服务端代码，停止旧进程后重新执行 `npm start`**。已有 `config.json` 不必重建，默认启用发现功能。
2. 在设备主页点击「搜索局域网服务器」。先用当前 Token 测试上次保存的地址；可用则展示该地址供点选，无需广播。想换服务器，可选「重新广播搜索」。
3. 上次地址不可用或尚未设置时，设备向局域网 UDP 3001 发起广播及已知地址定向请求，约搜索 4 秒，列出电脑名称、IP、HTTP 端口及是否需要 Token。同一地址只显示一次。
4. 点选服务器后验证 HTTP 服务并保存地址。若需要 Token 且当前 Token 不正确，会询问是否先保存地址，再打开 Token 输入框；可以取消。设置 Token 后可点击「测试连接」。
5. 没找到时保留原地址，并给出排查提示；仍可手动设置。搜索和点选不会下载安装插件。

PC 配置支持 `"discovery": false` 关闭发现功能；`"discoveryName": "My PC"` 设置显示名称，省略则使用电脑名。UDP 固定为 3001，不受 HTTP 的 `port` 设置影响；回复会携带实际 HTTP 端口。仅支持 IPv4，建议保留 `host: "0.0.0.0"`。绑定 localhost 的服务不能被其他设备访问。

防火墙需允许 **UDP 3001**，以及已有的 HTTP TCP 端口（默认 3000）。访客 Wi-Fi、AP 隔离、跨网段或路由器过滤可能阻止广播。UDP 端口被占用时服务端会警告，HTTP 手动连接仍可使用。

发现请求和回复不包含 Token、插件列表或源目录。设备仅使用 UDP 报文来源 IP 和合法端口，不采用回复中提供的任意 URL；发现机制不提供服务器身份认证，请在个人可信局域网使用。仅在手动点击时发送发现请求，不进行后台扫描。

PC 列表每页最多 4 行条目，插件分行显示名称、状态、本机版本与 PC 版本，右侧显示「下载」，标题显示筛选后数量与总数。点击条目后确认下载，下载完成再确认安装。

### 0.2.0 新增功能

- 主页直接显示当前服务器地址，点击该行修改；保存后立即刷新显示。
- 列表首项「刷新列表 / 筛选 / 排序」打开操作面板，可以留在列表内刷新。刷新失败保留原列表；刷新不会下载安装。
- 每次从主页获取列表，默认只显示「需要更新」（PC 版本较新的已安装插件）。未安装、未知、无法比较、同版本与降级不算需要更新；没有匹配项时显示空状态，可切换「全部插件」或「未安装」。
- 支持「更新优先 / 名称升序 / 名称降序」。更新优先时依次排列：PC 版本较新、未安装、目录冲突、版本未知或无法比较、PC 版本较旧、版本一致。同级按名称排列。列表内刷新保留当前筛选和排序，切换筛选排序不请求服务器。
- 下载显示真实已接收 KiB/MiB，校验解包显示文件，安装显示文件名、已完成/总文件数及进度条。下载过程中暂时没有总大小，不能提前计算百分比；完成校验后显示完成。进度约 0.7 秒刷新一次，适配墨水屏；网络和复制仍同步执行，不支持中途取消。
- 错误提示区分 Token 不匹配、超时、连接拒绝、插件不存在、PC 打包失败、磁盘空间不足、写入权限、包损坏及覆盖路径冲突，保留具体错误与文件名。
- 「安装结果记录」保存最近 50 条成功、失败、已安装但收尾失败的记录，也包含下载失败。显示插件 ID、版本、时间、服务器与详情；重启后仍可查看。取消下载后的安装不计为失败。Token 不写入结果详情。

安装文件复制成功后不会再提供重试安装，即使后续记录保存或临时文件清理失败，也会明确提示已安装及后续错误。自更新复制成功后仍要求重启。

「继续安装 / 重试安装」仅在本次会话确实存在待安装文件时显示。取消、安装成功或自更新完成后立即隐藏；重启后没有待安装任务，也不会显示。

插件使用独立页面：保存或取消地址/Token 设置、测试连接成功或失败后，关闭提示仍停留在插件页面；关闭 PC 插件列表回到插件主页。点击页面关闭按钮才退出。

1. 在工具菜单打开「PluginSync / 插件同步」。
2. 点击「搜索局域网服务器」点选并保存地址，或手动设置 PC 地址与可选 Token，点击「测试连接」。
3. 获取 PC 插件列表，默认查看需要更新的插件；首次安装请切换到「未安装」或「全部插件」。
4. 点击任意插件并确认下载，相同、较旧或未知版本均可下载。
5. 下载完成后确认是否安装，取消则清除本次临时文件。
6. 安装同路径文件覆盖、新文件新增、本机多余文件保留；首次安装创建目录。
7. 全部复制成功后清理临时文件，询问是否重启，可选择稍后重启。

安装失败时保留临时文件，使用「继续安装 / 重试安装」。不提供备份回滚，失败时可能已有部分文件被覆盖。待安装状态只保留在当前 KOReader 会话；退出后可以重新下载，下次下载会清理遗留临时文件。

新插件安装在 PluginSync 所在的插件父目录；更新会查找默认目录与 `extra_plugin_paths`。多处存在同名插件时拒绝操作，避免更新错副本。保护表中的内置插件仍禁止覆盖。

## 更新 PluginSync 自身（0.1.1 起）

将生成的客户端安装包解压到 PC 插件根目录，得到 `pluginsync.koplugin/`，然后像其他插件一样获取列表、下载并确认安装。自更新固定覆盖当前运行的 PluginSync 目录，兼容旧目录名 `pluginSync.koplugin`，不会因大小写不同另外创建副本。

自更新确认会说明需要重启。覆盖成功后暂停插件同步功能并询问重启；选择稍后重启也不会继续下载或安装其他插件，重启后恢复使用。临时文件正常清理，PC 地址和 Token 保存在独立设置目录中。

**已经安装的 0.1.0 仍会禁止自更新，必须先手动覆盖安装一次 0.1.1 并重启，后续才能使用自更新。** 自更新同样不提供备份回滚，尚未真机验证。

## 版本来源

PC 依次读取：

1. 插件内 `pluginsync.json`：`{"name":"Demo","version":"1.2.0"}`。
2. 插件根目录的 `versions.json`：`{"demo.koplugin":"1.2.0"}`。
3. `_meta.lua` 中受限文本匹配的 `version = "1.2.0"`，不执行 Lua。
4. 无可靠版本显示未知。

本机优先读取实际插件内元数据；仅在文件缺少有效版本时使用安装记录，并标注来源。PC 集中映射可用于不含版本的插件；如映射版本与本机文件内版本不一致，本机优先显示文件内版本，建议统一维护。外部更新的插件若仍没有任何版本文件，安装记录依然可能过期。

规范 SemVer 支持数字及预发布版本比较，如 `1.10.0 > 1.9.0`；其他字符串相同显示一致，不同显示无法比较。不扫描本机代码哈希，不因同版本代码变化提示更新。

下载确认以下载包对应版本为准。如果获取列表后 PC 修改了插件，安装使用已经下载的副本，不再次获取 PC 内容。

## 范围与限制

- 临时目录为 KOReader 数据目录的 `cache/pluginsync-download/`，安装确认前不写本机插件。
- 服务端输出标准 stored ZIP，客户端按 64 KiB 块读取，校验 HTTP 长度和文件 CRC-32，不依赖外部 unzip。不接受其他来源的任意 ZIP。
- 拒绝路径穿越、重复条目、符号链接条目和超限包；只允许同源 HTTP，不跟随重定向。
- 单次请求 5 秒阻塞超时、约 60 秒接收时限。首版网络与复制同步执行，操作时界面可能暂时无法响应。
- **暂不保护插件内的用户配置**：下载包含同路径配置时会覆盖。保留本机多余文件也意味着旧代码可能残留。
- 面向可信个人局域网，CRC 检测下载损坏，不提供发布者签名。
- 内置插件保护表随 KOReader 新增内置 ID 时需要维护。
- 下载时避免同时编辑 PC 源目录。服务端检查单文件读取期间的变化，不提供跨文件快照事务。

服务端：

```powershell

```

```powershell
node tests/make-fixture.mjs

```

客户端测试使用真实 LuaJIT 与文件系统/UI 适配器，验证模块逻辑及 Node ZIP 与 Lua 解包互通，不模拟 KOReader 屏幕和硬件。
